# v0.4.0 release notes

This release lets skills start from plain requests as well as from their names.
Each skill now ends with a suggested next step, and eight new skills join the set.
Skills can still be installed together or one at a time.

## Skills

| Skill | What it does |
| --- | --- |
| `repo-audit` | Read-only overview audit of a repository, with run history summaries and each finding routed to the skill that follows it up. |
| `verification` | Builds and maintains a project's verification kit and feature-map coverage gate, with a `correct` mode that turns a recurring mistake into an enforced, proven check. |
| `vision` | Drafts and stress-tests a project vision. |
| `glossary` | Creates and maintains a project glossary. |
| `architecture` | Creates and maintains a project's architecture document, including execution-context and wrapper boundary checks. |
| `foundation` | Sets up the foundation for a new project from an approved vision, with guidance on tool selection and optional pre-push checks. |
| `agents-md` | Maintains the project's agent instruction file, with size measurement and an instruction growth gate. |
| `maintenance` | Registers project documents and runs drift sweeps that say which maintain skill to run next. |
| `plan` | Writes one implementation plan from an approved design and never executes it. |
| `formal-verification` | New. Proves one stated property of a high-stakes spot by model checking, and leaves a project-local suite that the project reruns as the code changes. |
| `readme` | New. Creates or audits a README.md so people can find, understand and install the project, and so an agent can set it up and run it. |
| `no-mistakes-tuning` | New. Tunes a repo's no-mistakes gate so review stays on likely defects, fix loops stay bounded, and config-only changes skip agent review. |
| `how` | New. Explains how a part of a codebase works, with every claim cited to a file and line. |
| `why` | New. Explains why code, a rule or a decision exists, from git history, pull request review threads and any connected ticket or document source. |
| `teach` | New. Builds a cited mental model of an area of a codebase, covering how it works and why it is built that way. |
| `prototype` | New. Builds two or three throwaway variants of a design in scratch, measures each, and reports the evidence and a recommendation without writing to the repo. |
| `recall` | New. Summarizes prior context from this project's local Claude Code and Codex transcripts, read-only, with the summary kept in scratch. |

## What is new since v0.3.0

Skills start from plain requests.
Each skill description now says what the skill does and gives a "Use when" clause in plain words, so the agent can start a skill from a matching request such as "audit this repo" as well as from its name.
Each skill ends with one suggested next step that names a related skill to run or to ask the user about.
Eight skills are new, as listed above.
Verification adds fast-feedback guidance, safety guidance and maintenance impact checks, and extends kit setup and rule maintenance.
Repo audit adds read-only run history summaries.
Agents-md measures instruction size, extends its line audits and adds an instruction growth gate.
Foundation and maintenance add a no-comments policy and checks for the maximum length of code files.
Foundation also guides tool selection and optional pre-push checks.
Plan sizes its units so that each one can be a separately verifiable pull request.
Architecture adds execution-context and wrapper boundary checks.
Formal-verification bundles a pinned copy of the pstack statechart compiler, with its license.
The package check, run by `npm run check`, now requires each skill description to start with what the skill does and to include a "Use when" clause, requires each skill to end with a next-step suggestion that names a bstack skill, and fails when the bundled statechart compiler differs from its pinned source.
The check also type-checks the project and verifies the generated README.
